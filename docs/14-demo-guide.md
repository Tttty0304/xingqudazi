# 多用户演示脚本（Task13）

> 目标：在 15-20 分钟内完整展示产品的核心体验闭环 + 关键工程质量点。
> 建议开两个浏览器窗口（或一个正常窗口 + 一个隐私窗口，避免登录态互相覆盖），
> 分别登录 `demo_alice` / `demo_bob` 两个演示账号。

## 准备工作

```bash
# 1. 一键启动（若尚未启动）
docker compose -f deploy/docker-compose.yml up -d --build

# 2. 等待服务就绪
./scripts/smoke_test.sh http://localhost:8080

# 3. 预置演示数据（创建 demo_alice/demo_bob，建立好友关系，设置关注事项+生成AI推荐候选）
python3 scripts/demo_seed.py http://localhost:8080

# 4. （可选）跑一遍集成测试，向评审展示"接口都是真实可用的"，不是仅前端能跑通
python3 scripts/integration_test.py http://localhost:8080
```

浏览器打开 `http://localhost:8081`，两个窗口分别用 `demo_alice`/`demo_bob`
（密码 `Demo123456`）登录。

## 演示流程

### 第一部分：核心聊天体验（约 5 分钟）

1. **房间列表**：展示首页的兴趣房间列表（数码/追番/运动/美食），说明"预置固定
   房间，暂不开放用户自建"（Plan 问题#6 已确认的产品边界）。
2. **进群聊天**：alice/bob 窗口都进入同一房间（如"数码"），互相发消息，展示：
   - 实时双向收发（WebSocket，非轮询）
   - 在线人数实时更新
   - 消息展示真实用户名（不是用户 ID）
3. **发图片**：任一窗口点击 📷 上传一张图片，展示图片消息实时到达对方窗口。
4. **XSS 防护**：在消息框输入 `<script>alert(1)</script>` 发送，展示对方收到的
   是转义后的纯文本，不会执行脚本（Task8 系统安全性）。

### 第二部分：好友与私聊（约 5 分钟）

1. 打开 alice 窗口的"好友"页，展示已与 bob 互为好友（demo_seed 预置）。
2. 演示添加新好友的完整流程：alice 在"添加好友"输入框输入一个当前不存在的
   用户名，展示"用户不存在"的友好错误提示；再输入一个真实存在的第三个账号
   （现场可临时注册一个 `demo_carol`）演示发起请求 → 对方导航栏实时出现
   "好友•"未读提醒（**不需要刷新页面**，验证应用级共享 WebSocket 连接的效果）
   → 对方在好友页接受请求。
3. 点击 bob 卡片上的"发消息"，进入私聊页，双向收发消息，展示与群聊类似的
   实时体验；关闭该会话窗口重新打开，展示历史消息正确持久化加载。

### 第三部分：内容安全与可靠性（约 3 分钟）

1. **敏感词拦截**：任一窗口发送一条含内置演示敏感词的消息（如 `badword1`），
   展示该消息**不会**出现在聊天记录里（命中即拦截，不落库不广播）。
2. **举报**：对一条正常消息点击举报（若前端未接入举报入口，可直接用
   `curl`/Postman 演示 `POST /api/reports`），展示接口返回 `report_id`。
3. **限流**：连续快速发送 10 条以上消息，展示触发限流后的错误提示
   （Task6：2秒突发窗口 + 每分钟长期配额双层限流）。
4. **优雅关闭**：现场执行 `docker kill --signal=TERM deploy-server-1`，展示
   浏览器 WS 连接收到真实 Close 帧（而非静默断连），随后
   `docker compose -f deploy/docker-compose.yml up -d server` 恢复。

### 第四部分：AI-native 预留能力演示（约 5 分钟）

1. 打开"关注事项"页，展示 demo_seed 已预置的关注关键词（alice/bob 均含"摄影"）。
2. 打开"AI推荐"页，点击"生成/刷新推荐"，展示候选列表中出现匹配理由
   （"你们都关注：摄影"）与打分；点击"感兴趣"，再点击"加为好友"，展示
   AI 推荐到好友关系的完整闭环。
3. 打开"Web Push"开关（导航栏 🔕/🔔 图标），点击授权浏览器通知权限，说明：
   - 后端是纯 Go 实现的 RFC8291（消息加密）+ RFC8292（VAPID 身份声明），
     不依赖任何第三方推送 SDK
   - 演示时若离线私聊消息成功弹出系统通知，即完整走通端到端链路
4. 一句话说明架构预留：`docs/13-architecture-and-adr.md`「已知简化点」第4条——
   当前 AI 推荐是规则化简单实现，`pgvector`/`embedding`/`bot_action_log` 等字段
   已在 schema 中预留，可平滑升级为语义匹配与真实机器人代理，不是"完全没考虑"。

### 收尾：架构与工程质量一句话总结

> "整体是 Go+Gin+WebSocket 的后端，PostgreSQL+Redis 存储，Docker Compose 一键
> 部署；WS 广播强制走 Redis Pub/Sub，已用真实多容器环境验证跨实例广播；
> 限流/优雅关闭/结构化日志/XSS防护/CORS/敏感词过滤/举报 都是真机验证过的，
> 不是只写了代码没测过；测试方面 Go 单测覆盖 service 层核心逻辑，另外补了一份
> `scripts/integration_test.py` 做黑盒接口回归，golangci-lint 全绿。"

## 常见问题预案

- **图片显示 404**：容器重建后若之前挂载的 volume 被清空，历史图片会失效
  （media_uploads 卷正常情况下持久化，除非显式 `docker compose down -v`），
  当场重新上传一张即可，不影响演示效果。
- **Web Push 授权失败**：浏览器需要"安全上下文"（HTTPS 或 `localhost`）才允许
  订阅推送，`http://localhost:8081` 满足条件；若被用户手动拒绝过通知权限，
  需要在浏览器地址栏站点设置里手动重置权限后再试。
- **AI 推荐列表为空**：确认 `demo_seed.py` 已成功运行且两账号关注事项存在
  公共关键词；也可以现场用"关注事项"页临时加一条关键词再重新生成。
